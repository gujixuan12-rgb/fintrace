# 研报草稿测试样本（annotations）

本目录存放**待核查的研报草稿**及其**真值标注**。两者物理分目录，防止检测流程误读答案。

## 目录约定

    cases/       案例定义 —— 声明材料集、截止日、草稿与真值的路径，工具按此发现样本
    drafts/      待核查的草稿正文 —— 这是检测流程的输入
    evaluation/  逐条真值标注 —— 评测专用，严禁传入检测流程、提示词、检索索引

### TXX-DRAFT-2023-001（天下秀 2023 年报点评草稿）

- 数字全部取自天下秀《2023 年年度报告》（2024-04-22 披露，SHA256 `734c2a88…`）公开披露值。
- 选用这家公司的理由：它的 2023 年报**存在官方承认的披露差错**，更正公告 2024-04-23 发布，
  且原版、更正版与更正公告在巨潮都能取到，可以给出一份「官方认可的真值」。
  材料获取路径见案例文件 `cases/tianxiaxiu_2023_draft_case.json` 与 `data/sourced/`。
- 判定分布与第一家同为：支持 6 条、矛盾 6 条、证据不足 1 条；错误类型同样覆盖六类。
  两家同构，便于做对照实验，而不是只看单例。
- 预测截止日 2024-04-22：更正公告与更正版年报均为 2024-04-23 发布，一并被时间截断排除。

  不得引用更正公告。
- 误报控制负例：TXX-001～006 均为正确主张。其中 TXX-001/002 存在亿元↔元换算；

  TXX-005 的费用降幅与收入方向相反；以上均不得判为错误。
- 官方更正的另外 5 处（第 87/88/231/248/254 页：募集资金表的单位标注、子公司表表头、

  `correction_reference.note`。

## 标注要求（写新样本时必须遵守）

1. 每条主张给出 `expected_verdict`（SUPPORTED / CONTRADICTED / INSUFFICIENT）。
2. 判 CONTRADICTED 的必须给出 `error_type` 与 `suggested_fix`。
3. 判 INSUFFICIENT 的不得附正面证据，须写明 `missing_input`——缺什么就说什么，不许编页码。
4. 每条证据给出 `pdf_page` 与去空白后的 `quote`，且必须在对应页上可检索到。
5. 至少保留正确主张作误报控制负例，并在 `false_positive_note` 里写明为什么容易误报。
6. 新增样本时同步新增 `cases/<样本>.json`（声明材料、截止日、草稿路径、真值路径），
   自检脚本据此自动发现样本，不需要改脚本。
7. 必须声明 `annotation_scope`：真值已覆盖草稿**全部**可核验主张的写 `exhaustive`，否则写
   `partial`（并在 `annotation_scope_note` 里写清还缺哪几条）。这个字段决定评测口径 ——
   运行时多报的「矛盾」裁决：`exhaustive` 下计入 FP 并让评测脚本判失败；
   `partial` 下只能列「待审」，但同样不算通过。两种情况都不能凭「金标里没有它」就说没有误报。

## 自检

标注自身出错，评测即失效。写完必须跑自检：

    python tools/audit_annotation.py                      # 检查全部样本
    python tools/audit_annotation.py TXX-DRAFT-2023-001   # 只检查一个样本

它会核对每条证据的页码与数字是否真的能在源 PDF 上找到，并检查反证（引用页码错类，
被引页确实不含所引数值）、标注不变量，以及 summary 计数与 claims 实际分布是否一致。
样本从 `cases/*.json` 自动发现。
