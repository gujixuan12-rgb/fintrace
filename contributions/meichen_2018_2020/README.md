## 程序读取方式

`financials["2020"]["revenue"]` 等点对象保留 `value/unit/scope/source_id/page`，扩展字段记录原文和可用性。金额均取原报告精确“元”值，未使用概述中四舍五入的“万元”数字替代。金额和百分比为十进制字符串，应使用 `Decimal`。`unit_multiplier` 将原始单位转为 `base_unit`；百分比14.28对应比例0.1428。

`financial_observations` 存放有冲突、尚未选入统一指标的原始数值。`disclosures` 存客户、供应商、管理层与控制关系；这些记录也出现在CSV中。CSV的 `metadata_json` 保留角色、任期、匿名状态、引用片段等扩展字段，与JSON逐条对应。

在队长分支 `contributions/chen_yimin` 独立计算包的Python环境中，可以调用现有计算模块。下例以本README所在目录为工作目录读取 `original_inputs.json`；如果在仓库根目录运行，请把文件路径改成 `contributions/meichen_2018_2020/original_inputs.json`。独立计算包与根工程的同名 `fintrace` 包须分进程使用：

```python
import json
from pathlib import Path
from fintrace.source_guard import validate_sources
from fintrace.calculations import calculate_features

case = json.loads(Path("original_inputs.json").read_text(encoding="utf-8"))
assert validate_sources(case) == []
features = calculate_features(case["financials"])
```

本次已实际执行并返回8项指标。当前计算器主要计算2019/2020比较；2018已结构化保存，但现有函数不会自动新增2018指标。

新增计算读取任何点前，必须检查 `calculation_eligible`、`value`、`unit` 和 `scope`。`available_before_cutoff=true`只表示来源当时已公开，不保证某个存在矛盾的数值可以直接选用。`null`不能替换为0。现有队长计算器不会统一检查所有扩展字段，新写指标需显式执行这些检查。

## 页码与口径

- `page`是年报印刷页码，`pdf_page`为从1开始的PDF页序，本次使用的证据页二者一致。
- `citation_pages`包括正文及跨页表头；`quote_fragments`逐段标明页码。部分记录按原文逐行摘录并用 `header_pages` 标注表头所在页。
- 跨行金额经原始页面视觉核对；图中股权数字用 `evidence_format=figure_visual_transcription` 标明视觉转录，不伪装成可搜索文字层。
- 财务数据采用合并口径；归母净利润指合并利润中归属于母公司股东的部分，不是母公司单体利润。
- 客户供应商表没有直接标注“合并”，其口径按公司经营分析章节识别；记录中明确保存 `scope_explicit_in_table=false` 及判断依据。
- 2018/2019已完工未结算资产是存货组成，2020合同资产采用新收入准则列报。不得直接把三年的科目无说明地当成同口径连续序列。
- 减值准备余额、本期计提及减值损失分开；2018损失为正数费用，2019/2020相应损益按原表正负号保存。没有人为汇总出一个可能重复或遗漏的“全部准备总额”。
