# 项目记忆（fintrace-agent）

长期有效的事实与决策。**不记进度、不记临时状态**（那些看 `docs/STATUS.md`）。
接手前先读这份 + `README.md` + `docs/STATUS.md`。

## 一、这是什么，边界在哪

把 FinTrace 的核查逻辑重建成一个**自主调查的 Agent**，与团队仓库并行发展、互不干扰。
不改团队仓库任何一行；确定性内核以「复制 + 记录来源」搬进 `src/fintrace_engine/`（见 `docs/VENDOR.md`），
**只读**。新写的 Agent 层在 `src/fintrace_agent/`。

## 二、不可违反的纪律（改代码前先看这四条）

1. **判定不在模型手里。** 模型只做三件事：规划调查路径、语义抽取、必要的定性审查。
   数值比对、口径判断、适用条件、发布决定一律确定性代码。模型可以拉低结论（判 conflicted），
   但**不能批准**（不许把 semantic_status 标成 bound）。
2. **事实必须能回到原文。** 每条结论要能定位到「哪个文件、第几页、哪句话」；
   定位不到就留空并降级，绝不编页码。
3. **时间硬门管到底。** 晚于截止日的材料不进检索；历史回放模式下连**线索**也不进决策上下文
   —— 影响注意力就是泄漏。FILR 在历史回放下的红线是 0。
4. **报告必须带未解决清单。** 只报解决了的部分等于隐瞒。残余项、失败工具、待人工复核都要列。

## 三、口径口径（容易搞错的几组定义）

* **两轴状态**：`evidence_status`（W 门：原文存在/可定位/时间合法）与 `semantic_status`
  （B1~B4：概念/事件状态/统计范围/口径）。两边都过才算事实；只过 W 的不得支撑矛盾结论。
* **一手证据 vs 二手线索**：一手来自官方披露原件，逐条带页码可回查；二手（网页搜索）
  只用于指方向，不单独支撑任何结论。
* **引文回查按片段做**：引擎给出的引文是单元格片段（形如「营业收入 / （元） / 1,243,18」），
  整句在原文里找不到。判据是**每个实质片段都能在原件里找到**；数字片段按数字边界核对
  （截断的数字不算命中）。拿整句做字面子串匹配会把正常结论整批拦掉。
* **指标两套分开报**：`run_draft_eval.py` 是固定链路基线；六项新指标只在 `mode=="agent"`
  的 run 上算，固定链路运行一律排除在分母外，且必须在报告里写出排除了几个。
* **声明式抽取优先**：遇到没有现成提取器的格式，走 `t_spec_extract` 声明式规格
  （定位 + 抽取的 JSON 规格），**不执行模型写的代码**。`t_author_tool` 不启用。

## 四、关键决策与理由

| 决策 | 理由 |
|---|---|
| 独立版不 import 团队仓库 | 团队仓库封存中；两边互不干扰，实验不必迁就提交格式 |
| 默认自主规划，fixed 降为基线 | 用户要的是「调查路径由 Agent 自主决定、路径写死的只是安全边界与发布条件」 |
| 决策日志记模型原文响应 + 工具原始结果（大对象走内容寻址 blob） | 可重放性要被验证，不是口号 |
| 精度是带版本的知识，模型不能临时改 | 0.155 被截成 0.15 少算 90 万那次事故的教训 |
| 知识库改动一律人审 | 拿产生该知识的同一套回归去批准它，等于自证 |
| Relation 的适用条件由程序填 | 跨分红方案误报（同一年报四个方案/三个基数）靠字段级三元组挡 |
| 报告必须带未解决清单 | 隐瞒未解决项比结论保守更糟 |
| agent 模式下「主张 ↔ 断言」的配对目前按主体+期间+指标确定性匹配 | 先跑通闭环；更严谨要走知识库口径与「同值多页」判定（见 STATUS 不足 8） |

## 七、真模型实跑换来的硬规矩（照着改代码，别重犯）

1. **上下文必须让模型看得见三件事**：手边有哪些材料（含可用路径、截止日是否排除）、
   有哪些工具（参数契约 + 哪些不可用）、自己已经登记了什么（`header.registered`）。
   缺任何一块，模型就会联网找已经在手的年报、猜参数、重复解析。
2. **证据日志只能有一个实例**。回路若自己 `new` 一个，它读到的索引永远是空的，
   于是会告诉模型「还没解析」——明明刚解析完。
3. **超长列表会被内容寻址卸载**（`{"blob_ref","chars","type"}`）。登记前必须判断并回读，
   否则会把「1656 条 span」看成 0 条。
4. **只有真正新增的证据才算进展**。同一份材料重复解析如果每次都报「新证据」，
   每步都像有进展，打转守门永远不触发。
5. **守门的前置条件必须镜像工具的真实参数**（`t_recall` 是 `keywords/page_from/page_to`，
   `t_knowledge` 必填 `op`）。写错了会造成两种坏结果：拦掉正确调用，或放行注定失败的调用。
6. **材料侧只登记能归一到知识库指标的数值断言**。规则拆解跑在整份年报上会产出
   「赛特广场5层」「不适用」这类噪声，W1/W4 会照数拒收 —— 门没错，是源头不该生成。
7. **一次别解析整本年报**：`t_parse` 的 `pages` 支持页码列表或 `"7-9"`，按页分批取。
8. **候选断言必须绑到「已登记的原文片段」**：`source_spans` 不许自己拼 id，必须指向证据库
   里真实存在的 span（按同页 + 引文或数值匹配）；找不到就不登记。校验器还要拿到被引用的
   span 对象本身，否则 W4 会判「未绑定任何原文 span」——实测 48/48 全拒。
9. **给模型的提示不许承诺工具做不到的事**：我曾经在硬提示里让模型「按页分批解析」，
   而当时的 `t_parse` 只能整本解析 —— 提示与契约不一致，模型就会一遍遍做无用功。
   改提示之前先确认工具真的支持。
10. **`raw_text` 必须是披露的那个数**（如 ``0.0718`` 四位小数原样），整行文字放 ``text``。
    塞整行进去，W6 会判「不是纯数字串、无法判定披露精度」，整批候选被拒。
11. **真实 PDF 的表格有三件事必须处理**：标签跨行（``归属于上市公\n司股东的净利\n润（元）``）、
    数值跨行（``1,243,188,17\n0.21``）、单位写在数值前面（``营业收入（元） 2023年 1,243,...``）。
    三样任一不处理，整页表格就抽不出东西；而 W 门的拒收理由（W1/W4/W6）是定位这些问题的线索。
12. **断行拼接要带守卫**：只拼「明显没写完」的形态（千分位分组 1~2 位、小数位被切断），
    不能见换行就拼 —— 否则会把上一行末尾的数字和下一行的年份粘成怪数。
13. **事实 = 两轴都过**（W 门的 `attested` + 语义绑定的 `bound`）。只过 W 的进不了判定：
    `only_facts=True` 会把它挡在外面。所以材料侧的表格行必须做成 ``table_row`` 切片并填好
    ``bound_context``（行标/单位/期间/范围），否则 B3 判不出统计范围，断言永远停在 unbound。
14. **跨单位比较交给程序做**：换算到主张的单位，再按**主张披露的精度**对齐（主张写 2 位小数
    就不能拿全精度硬比，否则「2,931.56 万元」这种正确写法会被误判成错）；``元/股`` 与 ``元``
    按 1:1 处理（草稿常把每股指标单位写成「元」）。判不出就老实报「单位不可比」，不许硬比。
15. **期间要归一**：材料写「2023年」、草稿写「2023A」，字符串直接比会全部命不中。
16. **判定结果要回写 state.json**：判定发生在回路之后，不回写的话报告与指标读到的还是旧状态。
