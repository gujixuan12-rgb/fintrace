## 长期不变量（不要改坏）

1. **系统只输出风险信号，不做定性结论。** 这是比赛合规底线，也是措辞约束存在的理由。
   实现位置 `verification/wording_guard.py`，报告出场前强制校验。
2. **预警计算只能用截止日之前发布的材料。** 实现位置 `verification/cutoff_filter.py`。
   这是防止「未来信息泄漏」的唯一防线 —— 用更正公告去预警更正之前的事，等于作弊。
3. **数字必须来自 Python 复算。** 模型负责检索、假设与措辞；算术归 Python。
4. **页码可追溯是卖点，不是可选功能。** 定位不到就诚实地输出「无法确认」。

## 关键设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 模型 vs 规则 | 先规则后模型 | 先用确定性规则把主干和格式跑通，再接 LLM；否则调试时无法区分「规则错」还是「模型错」 |
| 包结构 | `src/fintrace/<五子模块>/` | 比队长的 `src/<五子模块>/` 多一层包名，Python 导入与打包需要 |
| 约束位置 | 代码层，非提示词 | 提示词约束不可验证；代码层可测试、可回归 |
| mock 公司 | 虚构公司 | 避免把编造的数字安到真实上市公司头上 |

## 已知缺口（当前无法回答的问题）

1. **没有真实数据。** `data/raw/` 为空。齐飞扬有 `财报更正案例_6组.zip`（约 35MB），
   陈颖孜有美晨生态完整链条 —— 都是**更正类**（事后）材料，
   与已定的**事前预警**方向不完全对齐，需要队长明确用哪一套做首个案例。
2. **没有评测集。** 事前预警没有 ground truth，「准确率」目前无法定义。
   这是本项目最大的方法论风险，需要团队先定评价口径。
3. **没有接大模型。** 研报主张拆解、异常假设生成这两步最终需要 LLM。

## 验证方式

- 报告输出后 grep 一遍黑名单词，确认措辞约束真的生效（不能只信单测）。
